Archive guide: preserving the evidence

How to read a source archive, verify a hash, and keep a procurement investigation reproducible.

Open the interactive view →

The archive view is the memory of an investigation. It stores the documents, hashes, retrieval dates, and descriptions that make a claim checkable later. A source archive is not a pile of links. It is a chain of custody for public evidence.

Data status: the interactive view uses a labelled demonstration dataset. This guide explains how to read the interface and how to verify a real record.

What the archive view shows

The archive view lists documents with a name, a hash, a date, and a status. In the demo, the entries are synthetic. In a real investigation, each entry should point to a retrievable document or a preserved copy, and the hash should allow a reader to check that the file has not changed.

The archive is especially important for procurement because portals change. A notice can be removed, an award can be amended, and a PDF can be replaced. A dated copy and a hash make the original state reproducible.

Why hashes matter

A cryptographic hash is a fingerprint of a file. If the file changes, the hash changes. That does not tell you whether the change is legitimate or illegitimate; it tells you that the file you are looking at is not the file that was archived. For a researcher, that is a useful warning.

The archive should record the retrieval date, the URL, the file type, and the hash. If the document is a web page, record the version and the capture date. If the document is a PDF, keep the original file and do not re-save it through a tool that changes metadata.

Reading an archive entry

Start with the document name and the publisher. Is it a primary source or a secondary source? Then check the date. Is it the publication date, the award date, or the retrieval date? Then check the hash. Does it match a copy you can verify? Then check the description. Does it tell you what the document proves and what it does not prove?

A good archive entry is boring and precise. A bad one is vague and confident. The archive should make it easy to disagree with the article, because that is how public-record research improves.

Limits and common errors

An archive cannot preserve everything. Some documents are behind paywalls, some are redacted, and some disappear before they can be captured. The archive should record those gaps. A missing document is not a reason to invent a finding; it is a reason to qualify the claim.

Common errors include archiving a search-results page instead of the document, recording a URL that requires a login, and treating a hash as proof of authenticity rather than proof of integrity. A hash proves that a file has not changed since it was hashed; it does not prove that the file is accurate or complete.

Frequently asked questions

Are the archive entries real documents?

The interactive archive uses demonstration entries. They are not real source documents. The investigations link to real public records in their source lists.

What is a SHA-256 hash?

It is a cryptographic fingerprint of a file. If the file changes, the hash changes. It is used to show integrity, not authenticity.

Why preserve a document if the original URL still works?

Because URLs change, pages are updated, and portals remove old records. A dated copy and a hash make the evidence reproducible.

Does a hash prove a document is true?

No. It proves that the file has not changed since it was hashed. The content still needs to be read and verified.

What should I do if a source disappears?

Record the date it was last available, keep any preserved copy, and describe the gap in the article. Do not substitute an unrelated source.

Can I use the archive to check an article?

Yes. Start with the source list at the end of the article, then compare the cited document with the claim. If the link is dead, contact the publication for the preserved copy.
